# ビスケット(愛犬デスクトップマスコット MVP)

「ビスケット」という名前の愛犬が、昔のMicrosoft Officeアシスタント「カイル」のように画面に常駐して、歩いたり・クンクンしたり・あくびしたり・お手をしたり・回ったり・寝たりする、愛犬をモチーフにしたデスクトップマスコットアプリのMVP(最小構成版)です。

## 動作環境

- Mac(将来的にWindowsにも展開予定。今回のコードはElectronベースなので、Windowsでもほぼそのまま動作するはずです)
- Node.js(18以降推奨)

## 開発中の動かし方(ターミナルを使う方法)

ターミナルでこのフォルダに移動して、以下を実行してください。

```bash
npm install
npm start
```

初回は`npm install`でElectron本体などをダウンロードするため少し時間がかかります。`npm start`で画面右下あたりに愛犬が表示されるはずです。

## ダブルクリックで起動できる.appにする(配布・日常使い向け)

毎回ターミナルを開くのは面倒なので、普通のMacアプリと同じようにダブルクリックで起動できる`.app`を作れます。

```bash
npm run dist
```

これを実行すると`dist`フォルダの中に`.dmg`(インストーラー)と`.app`が作られます。`.dmg`をダブルクリックして、中のアプリをアプリケーションフォルダにドラッグすれば、以降はLaunchpadやアプリケーションフォルダから普通に起動できます。

ビルドで出てくるのは`Biscuit.app`です。Finder・Dock・メニューバーでの表示も「Biscuit」になります。

`Info.plist`には`CFBundleDisplayName`として「ビスケット」も入れてありますが、**このアプリは無署名ビルドなので、macOSはこの表示名を採用しません**(electron-builder も無署名ビルドでは「macOS localized description not visible」と警告します)。カタカナで表示したい場合は、アプリケーションフォルダに入れたあと`.app`のファイル名を`ビスケット.app`にリネームすれば表示は変わります(起動も問題ありません)。ただし過去に一度、リネームが勝手に英字名へ戻った事例があるので、安定して使いたいなら`Biscuit.app`のままを推奨します。

`.app`のファイル名を半角英字にしているのは、後述のクラッシュ対策でアプリの内部名(`CFBundleName`)を半角英字にする必要があるためです。日本語のファイル名でも起動はしますが、インストール後に手でリネームする運用では名前が元に戻ってしまう事例があったため、**名前は`package.json`の`productName`で指定し、ビルドのたびにその名前で出てくる形にしています。**

はじめて`.app`を開くときは「開発元が未確認のため開けません」と表示されることがあります(下記参照)。

## Macで「開発元が未確認」と表示された場合

このアプリはまだ署名(コード署名/公証)をしていないビルドです。`.app`をFinderで開こうとして警告が出た場合は、アイコンを右クリックして「開く」を選ぶか、システム設定の「プライバシーとセキュリティ」の一番下に出る「このまま開く」を選んでください。一度許可すれば、次回からは通常通りダブルクリックで開けます。

## 「予期しない理由で終了しました」というクラッシュについて(解決済み)

**2026-09-12に原因を特定し、修正済みです。** 記録として残しておきます。

### 症状

`npm start`(開発モード)では正常に動くのに、`npm run dist`で作った`.app`だけが起動直後に`EXC_BREAKPOINT (SIGTRAP)` / `Trace/BPT trap: 5`でクラッシュする。エラー出力は一切出ない。

### 原因

**アプリのバンドル名(`Info.plist`の`CFBundleName`)に日本語(非ASCII文字)が入っていたこと**でした。

`package.json`の`build.productName`が`"愛犬デスクトップマスコット"`だったため、electron-builderが`CFBundleName`にもその日本語名を書き込みます。Chromium(Electronの土台)は`CFBundleName`をもとに内部のヘルパープロセスのパスなどを組み立てるため、ここが非ASCIIだと起動処理の途中で致命的エラーになり、ログを出す前に即死します。`app.whenReady()`が呼ばれる前に落ちるので、アプリ側のコードは一切関係ありません(main.jsを空にしても同じようにクラッシュします)。

署名の有無・ASAR整合性チェック・Rosetta・JIT制限は、いずれも原因ではありませんでした。

### 対策

`package.json`の`build`を次のようにしています。

```json
"productName": "Biscuit",
"mac": {
  "extendInfo": {
    "CFBundleDisplayName": "ビスケット"
  }
}
```

- `productName`を半角英字にする → `CFBundleName`・実行ファイル名・ヘルパーアプリ名がすべてASCIIになり、クラッシュしなくなります。
- `CFBundleDisplayName`に日本語名を入れる → 署名済みのビルドなら表示名に使われます。無署名だとmacOSに無視されるため、現状の表示は`productName`(=`Biscuit`)のままです。

**`productName`を日本語に戻すと、またクラッシュします。**

### 日本語でなければならないもの / ASCIIでなければならないもの

実機で切り分けた結果は次のとおりです。

| 項目 | 日本語にできるか |
|---|---|
| `.app`のフォルダ名 | **できる**(起動確認済み。ただし上記の理由で英字にしています) |
| `.dmg`のファイル名 | できる |
| `Info.plist`の`CFBundleDisplayName` | できる(ただし無署名ビルドでは表示に反映されない) |
| `Info.plist`の`CFBundleName` | **不可**(これがクラッシュの原因) |
| 実行ファイル名(`Contents/MacOS/...`) | 不可 |
| ヘルパーアプリ名(`... Helper.app`など4つ) | 不可 |

Chromiumは`CFBundleName`をもとに`<CFBundleName> Helper.app`というパスを組み立てるため、内部名とヘルパー名はセットでASCIIにそろえる必要があります。一方、外側の`.app`のフォルダ名はどこからも参照されないので自由です。

## カーソルが手のひらの形に変わるしくみ(macOSの制約と対策)

撫でるイメージを出すため、ワンコの上ではカーソルが手のひら(`cursor: grab`)になるようにしています。ただしmacOSには次の制約があります。

**macOSでは、最前面でないアプリはマウスカーソルの形を変えられません。** `NSCursor.set()`・`cursorUpdate`・`cursorRects` のいずれもアプリが非アクティブだと無視されます。このアプリはDockアイコンを隠した常駐アプリなので普段は非アクティブで、そのままではCSSの指定が効かず矢印のままでした。

そこで `main.js` では、**カーソルがワンコの上に0.3秒とどまったら、このアプリを一瞬だけ最前面にし、カーソルが離れたら元のアプリに戻す**という処理を入れています(`updateHoverFocus`)。

実装上のポイントは3つです。

- **0.3秒の待ち時間**(`HOVER_ACTIVATE_MS`)。カーソルがたまたま通り過ぎただけでフォーカスを奪わないようにしています。
- **元のアプリの特定に `lsappinfo` を使用。** AppleScript(System Events)経由だと「操作の許可」ダイアログが出てしまうため避けています。`lsappinfo` は権限不要です。戻すときは、そのアプリがまだ起動しているかPIDで確認してから `open -a` で最前面に戻します(終了済みのアプリを勝手に再起動しないため)。
- **「ユーザーが離れた」と「ワンコが歩いて離れた」を区別しています**(`CURSOR_MOVED_PX` / `MOVE_SETTLE_MS`)。カーソル自体が20px以上動いていれば、撫でるのを終えたと判断してすぐ(約0.6秒)元のアプリに戻します。一方、カーソルが止まったままでワンコが歩いて下から外れただけの場合は、戻さずに待ちます(ウィンドウが動いてから3秒間)。区別しないと、「歩く」の1往復ごとにメニューバーが2回ちらつきます。
- **撫でている途中でユーザーが別のアプリに切り替えた場合は、フォーカスを戻しません**(`win.isFocused()` で確認)。切り替えた先から引きはがしてしまわないためです。

副作用として、**撫でている間だけメニューバーの表示がアプリ名に切り替わります。** これはmacOSの仕様上避けられません。気になる場合は、カーソルの形は諦めて「ウィンドウの中に手のイラストを出す」方式に変えることもできます。

## メニューバーのアイコンについて

起動すると、画面上部のメニューバーに小さな愛犬アイコンが表示されます。ここをクリックすると次のメニューが出ます。

- ビスケットを表示 / ビスケットを隠す
- ログイン時に自動起動(チェックを入れるとMac起動時に自動で立ち上がります)
- 終了(アプリを完全に終了します)

Dockアイコンは表示されない設定にしているので、普段はメニューバーのアイコンから操作してください。

## 今の実装でできること

- 「撫でる」を中心にした仕様になっています。基本は常に寝ていて、マウスカーソルをワンコ(ウィンドウ)の上に乗せると、カーソルが手のひらの形に変わり、撫でられたことに気づいて起きます。
- 起きたら、あくび・伸び→軽く歩く→クンクン、という一連の反応をした後、カーソルが乗ったままの間は、お手・回る・クンクン・あくび・待機・嬉しそうな顔・骨をくわえて走る・手を舐める・仰向けに転がって遊ぶ・はしゃいでお辞儀、をランダムに繰り返します。
- 「歩く」動作だけは実際に画面上を移動します。左右どちらかのランダムな方向へ100〜200pxほど歩いて行き、その場でくるっと振り返ってから、元にいた位置まで正確に歩いて戻ります(画面端が近い場合は、はみ出さない距離に自動調整します)。歩いている途中でカーソルが離れても、一旦歩き出したら振り返って戻ってくるところまでは必ず最後まで行い、戻ってきてから改めて「撫でられているか」を判定します。
- カーソルがワンコから離れると、その場でまた眠りに戻ります。
- 寝ている間(カーソルが乗っていない時)も、平均20秒に1回程度のランダムなタイミングで、時々起きて「あくび・伸び」か「手を舐める」のどちらかをランダムに行ってからまた寝る、という仕草を挟みます(撫でるとは無関係の、寝ている間だけのちょっとした演出です)。
- 各動作は、AI生成動画から抽出した複数コマの本格的なアニメーション(パラパラ漫画)になっており、脚の動きや表情の変化がなめらかに表現されます。
- ウィンドウは常に最前面・背景透過・枠なしで、ドラッグしてお好きな位置に動かせます(撫でている間にドラッグした場合もそのまま撫でた反応が続きます)。ドラッグはJavaScript側で自前実装しており(macOSの標準的なドラッグ領域機能は使っていません)、これによりカーソルが手のひらの形にきちんと変化します。
- メニューバー常駐、ログイン時自動起動のオン/オフ、表示・非表示・終了に対応しています
- 表示サイズは初期版の2/3程度に縮小しています(お好みでstyle.cssの`max-height`とmain.jsの`winW`/`winH`で調整可能です)

## 今回のバージョンで簡略化している部分(次の改善候補)

- 現在はクリックスルー(ウィンドウの上を素通りして下のアプリを操作できる機能)は実装しておらず、ウィンドウ全体がドラッグ領域になっています。作業の邪魔にならないようにしたい場合は、クリックスルーの実装を追加できます。
- Windows版としての動作確認はまだ行っていません。Electronの機能自体はクロスプラットフォームですが、実機での見え方の調整が必要になる可能性があります。
- コード署名・公証はまだ行っていないため、`.app`配布時に「開発元が未確認」の警告が出ます。自分だけで使う分には問題ありませんが、他の人に配る場合はApple Developerアカウントでの署名が必要になります。
- アニメーションのコマはAI生成動画から自動抽出したもので、ごく一部のコマに小さな色抜けの点が残っている場合があります。気になる箇所があれば教えてください。

## フォルダ構成

```
dog-desktop-pet/
├── package.json
├── main.js         # Electronのメインプロセス(ウィンドウ生成・移動処理・メニューバー・カーソル監視)
├── preload.js      # レンダラーからメインプロセスへの安全な橋渡し
├── index.html
├── style.css
├── renderer.js     # 撫でる操作に応じた行動フロー(寝る→起きる→歩く→クンクン→ランダム反応)
├── assets/
│   ├── anim/       # 各動作の複数コマアニメーション(stand/walk/sniff/yawn/paw/smile/spin/sleep/lick/run/roll/bow)
│   ├── dog_*.png   # 旧バージョンの1枚絵ポーズ(現在は未使用、参考用に残置)
│   └── tray_icon*.png
└── build/
    └── icon.png    # アプリアイコン(.app/.dmg用)
```
